# ShineRoster — النسخة المبسّطة مع لوحة الأدمن

نسخة تعليمية حسب القائمة المتفق عليها: HTML وCSS وPHP بأسلوب OOP، دون JavaScript أو Bootstrap أو Frameworks.

## التشغيل

1. احتفظ بنسخة احتياطية من مجلد المشروع وقاعدة بياناتك.
2. فك الأرشيف في مجلد نظيف باسم `ShineRoster` داخل `htdocs`، وشغّل Apache وMySQL في XAMPP.
3. إذا كانت قاعدة البيانات السابقة موجودة، استخدمها كما هي. لا تستورد ملف تركيب كامل فوقها. الكود يعمل دون استخدام الـViews أو جدول `auth_limits` الموجودين في النسخة القديمة، ولا يحذفهما.
4. لقاعدة جديدة فقط: استورد `database/shineroster.sql` دون حسابات تجريبية، أو `database/shineroster_with_demo.sql` مع البيانات المترابطة. اختر ملفاً واحداً.
5. إذا كانت قاعدة قديمة تفتقد جدول الرسائل فقط، استخدم `database/add_contact_table.sql`.
6. إعدادات الاتصال في `classes/Database.php`: المضيف `127.0.0.1`، القاعدة `shineroster`، المستخدم `root` وكلمة المرور فارغة. عدّلها لتناسب جهازك.
7. افتح `http://localhost/ShineRoster/`، أو المسار الموافق لمجلدك مثل `http://localhost/php/ShineRoster/`.

المتطلبات التي اختُبرت عليها النسخة: PHP 8.3 وMariaDB 10.11، مع PDO MySQL وmbstring. أبقِ ملفات `.htaccess` في أماكنها؛ فهي مخصصة لـApache. إعدادات Apache على جهازك لم تُختبر مباشرة.

## حسابات التجربة

- مقدم خدمة: `provider1@shineroster.test`
- زبون: `customer1@shineroster.test`
- الأدمن: `admin@shineroster.test`
- كلمة المرور للحسابات التجريبية: `ShineDemo!2026`

هذه الحسابات موجودة في ملف البيانات التجريبية فقط. الأسماء والبريد والرسائل أمثلة مصطنعة. المواعيد التجريبية مكتوبة كتاريخ صريح، ويمكن تعديلها إذا أصبحت قديمة.

## ما الأسلوب المستخدم؟

- متغيرات ومصفوفات، وشروط `if / else`، وحلقات `for` و`foreach`.
- كلاسات عادية، خصائص، كونستركتر ودوال عادية، دون وراثة أو دوال مجهولة أو تحميل تلقائي.
- `require_once` لتحميل الملفات و`session` لحفظ حالة الدخول.
- PDO باستخدام `prepare` ثم `execute` ثم `fetch / fetchAll`.
- استعلامات التشغيل: `SELECT`, `INSERT`, `UPDATE`, `DELETE`، مع `WHERE`, `AND / OR`, `ORDER BY`, `LIMIT` عند الحاجة؛ كل استعلام على جدول واحد.
- تجميع البيانات وربطها والبحث والإحصائيات والترتيب والتقسيم إلى صفحات يتم بحلقات PHP.
- `password_hash` و`password_verify` لكلمات المرور، و`htmlspecialchars` لعرض النصوص، ودوال النصوص والتواريخ المعتادة.

لا يوجد في كود PHP: `JOIN`، استعلام داخلي، `COUNT / AVG / SUM`، `GROUP BY`، Transactions أو `FOR UPDATE`، استثناءات أو callbacks أو Arrow functions أو `match`.

ملفات التركيب الجديدة تحتوي 9 جداول عادية مع المفاتيح الأساسية والأجنبية، دون Views أو Procedures أو أعمدة مولّدة. حُذف جدول تحديد محاولات الدخول من التركيب الجديد لأنه لم يعد مستخدماً. هذا لا يتطلب حذف أي جدول من قاعدة موجودة.

## ترتيب الملفات

- `classes/Database.php`: الاتصال بقاعدة البيانات.
- `classes/Auth.php` و`User.php`: الحسابات والدخول والصلاحيات.
- `classes/Admin.php`: وظائف إدارة الموقع؛ الاستعلامات فيه على جدول واحد أيضًا.
- بقية الكلاسات: الخدمات والمواعيد والحجوزات والتقييمات والرسائل.
- `classes/SiteData.php`: يقرأ الجداول باستعلامات منفصلة، ثم يبحث عن السجلات المرتبطة بحلقات. مثال: يجد الخدمة بواسطة رقمها، ثم يجد مقدمها بواسطة `provider_id`. هذا بديل تعليمي لـJOIN. يحتوي أيضاً دوال الإحصائيات والترتيب وتقسيم النتائج إلى صفحات.
- `includes/init.php`: يبدأ الجلسة، ويحمل الكلاسات، ويعرّف المساعدات العادية، وينشئ الاتصال.
- بقية `includes/`: الهيدر والفوتر والسايدبار المشتركة.
- `provider/`: صفحات مقدم الخدمة.
- `admin/`: صفحات صاحب الموقع؛ والهيدر والسايدبار والفوتر مشتركة داخل `admin/includes/`.
- ملفات PHP في الجذر: الصفحات العامة وصفحات الزبون.
- `css/` و`images/`: التنسيق والصور.
- `database/`: التركيب والبيانات التجريبية.

الكلاس يرجع `false` عند الخطأ، ويمكن قراءة الرسالة من `getError()`؛ الصفحة تعرض الرسالة باستخدام شروط عادية. الكود يحتفظ بالدخول حسب الدور، وملكية الخدمات والحجوزات، والتأكد من السعر من قاعدة البيانات، والتحقق العادي من الموعد قبل الحجز، والإلغاء والتقييم والتواصل. لوحة الأدمن مكتملة، والدخول إليها من صفحة تسجيل الدخول المشتركة بحساب صاحب الموقع.

## لوحة الأدمن

بعد تسجيل الدخول بحساب الأدمن ينتقل تلقائيًا إلى `admin/dashboard.php`. التسجيل العام لا يتيح إنشاء حساب أدمن، وإضافة الحسابات من لوحة الإدارة تقتصر على الزبون ومقدم الخدمة. إذا كانت قاعدة بياناتك السابقة موجودة، استعمل بيانات حساب الأدمن الموجود فيها؛ بيانات التجربة المذكورة أعلاه تخص ملف التركيب التجريبي.

| الصفحة | الوظيفة |
| --- | --- |
| `admin/dashboard.php` | أعداد الحسابات والخدمات والحجوزات، الحالات، قيمة الزيارات المكتملة، وآخر الحجوزات والرسائل |
| `admin/users.php` | بحث وتصفية وتقسيم نتائج، إضافة حساب زبون أو مقدم خدمة، تعديل بياناته وتفعيله أو تعطيله وحذف الحساب غير المرتبط ببيانات |
| `admin/providers.php` | إدارة المدينة والنبذة والمهارات، بما فيها استكمال ملف مقدم الخدمة |
| `admin/services.php` | عرض الخدمات وأصحابها وأسعارها ومددها، التحكم في ظهورها وحذف الخدمة التي لا توجد لها مواعيد |
| `admin/appointments.php` | تصفية المواعيد، فتح أو إغلاق المستقبلية، وحذف غير المرتبط بحجوزات |
| `admin/bookings.php` | جميع تفاصيل الحجوزات، إلغاء الحجز المؤكد أو إكماله بعد انتهاء الموعد |
| `admin/reviews.php` | البحث في التقييمات وإظهارها أو إخفاؤها أو حذفها؛ الإخفاء يزيلها من التقييم العام |
| `admin/messages.php` | قراءة رسائل التواصل، فتح تطبيق البريد للرد يدويًا، وحذف الرسائل |
| `admin/skills.php` | إضافة المهارات وتعديلها وحذف غير المسندة إلى مقدمي خدمة |
| `admin/account.php` | بيانات صاحب الموقع وكلمة مروره؛ الحفظ يتطلب كلمة المرور الحالية |

الهيدر ثابت مع التمرير، والسايدبار يتحول إلى برغر عند 800 بكسل فأقل، والرابط الحالي يتفعّل تلقائيًا. الإضافة لا تحتاج أي تعديل يدوي على `include` أو الروابط، ولا تغيّر مخطط قاعدة البيانات عن نسخة الأساسيات السابقة.

حساب صاحب الموقع محمي من التعطيل والحذف. الحسابات التي لديها حجوزات مؤكدة يجب تسوية حجوزاتها أولًا قبل تعطيلها. الحسابات والخدمات والمواعيد المرتبطة بتاريخ حجوزات لا تُحذف بصورة تكسر الترابط؛ يمكن تعطيل الحساب أو الخدمة بدلًا من ذلك. إلغاء حجز بواسطة الأدمن متاح لأي حجز مؤكد، والإكمال متاح بعد نهاية الموعد. إنشاء الخدمات وتعديل تفاصيلها وأسعارها وإضافة المواعيد تظل مسؤولية مقدم الخدمة، والأدمن يدير العرض والإشراف وفق الاتفاق.

إجمالي قيمة الحجوزات المكتملة هو قيمة الخدمات، وليس إيرادات الموقع أو مدفوعات محصلة. رابط الرد على الرسالة يفتح تطبيق البريد؛ لا يرسل الموقع رسالة تلقائية. طلبات الحذف تمر بخطوة تأكيد ظاهرة في الصفحة دون JavaScript.

## حدود نسخة الأساسيات

هذه نسخة للتعلم والتشغيل المحلي. أُزيلت حماية CSRF وتحديد محاولات الدخول وقفل العمليات والمعاملات للالتزام بالتبسيط. التحقق من توفر الموعد يتم قبل الحفظ، ولا يضمن منع تعارض طلبين متزامنين في قاعدة التركيب المبسطة الجديدة. وقد تبقى بعض التعديلات محفوظة إذا فشلت خطوة لاحقة لأن الحفظ ليس ضمن Transaction. تحميل الجداول ومعالجتها بحلقات مناسب لحجم التدريب الصغير، وليس بديلاً عن استعلامات الربط والفهارس في مشروع كبير.

## التحقق من هذه النسخة

- 55 ملف PHP اجتازت فحص الصياغة.
- الاستعلامات الـ84 الموجودة في PHP صريحة وعلى جدول واحد، دون ربط أو استعلامات داخلية أو تجميع SQL.
- نجح 159 فحص HTTP لوظائف الأدمن وصلاحيات الصفحات والإضافة والتعديل والتفعيل والحذف وحماية السجلات المرتبطة وكلمة مرور صاحب الموقع. تكررت بنجاح على قاعدة التركيب الجديدة وقاعدة النسخة القديمة دون ترقية.
- نجحت أيضًا فحوص الزبون السابقة: 29 للمنطق و28 عبر HTTP، و55 فحصًا للصفحات والوظائف العامة ومقدم الخدمة، مع تحديث توقع دخول الأدمن إلى لوحة تعمل.
- نجح 535 تأكيدًا بصريًا آليًا على Chromium لثلاث عشرة حالة عرض تشمل الصفحات العشر ونماذج التعديل، على مقاسات 320 و390 و768 و800 و801 و1024 و1440، مع مراجعة الصور بصريًا.
- نجح 11 فحص تفاعل فعلي في المتصفح لإنشاء حساب ومهارة وتعديلهما وحذفهما بتأكيد، وعرض خطأ كلمة مرور الأدمن دون إعادة تعبئة حقلها.

هذه الأعداد تأكيدات داخل سيناريوهات وليست كلها سيناريوهات مستقلة. الفحص على بيانات معزولة وخادم PHP محلي باستخدام PHP 8.3 وMariaDB 10.11، وليس قاعدة بياناتك الحقيقية أو إعدادات Apache على جهازك. الاختبار البصري لهذه الإضافة على Chromium. لا يحتوي الأرشيف أدوات الاختبار أو قواعد الفحص أو صوره أو مجلد verification أو Git.
