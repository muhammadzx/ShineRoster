# ShineRoster — النسخة المصحّحة

المشروع HTML / CSS / PHP بأسلوب OOP وقاعدة MySQL/MariaDB، دون JavaScript.
تم إصلاح النسخة الموجودة، مع إبقاء تطوير واجهات الزبون والأدمن لمرحلة لاحقة.

## تشغيل النسخة على XAMPP

1. احتفظ بنسخة احتياطية من مجلدك وقاعدة بياناتك الحالية. فك الأرشيف في مجلد نظيف اسمه `ShineRoster` داخل `htdocs`، بدلاً من دمج الملفات مع نسخة قديمة.
2. شغّل Apache وMySQL. المتطلبات: PHP 8.1 أو أحدث، وامتدادات `pdo_mysql` و`mbstring`، وMySQL 8.0.16+ أو MariaDB 10.4+.
3. إذا لديك قاعدة البيانات الحالية، استورد **فقط** `database/upgrade_security.sql` من phpMyAdmin. يضيف جدولي الحماية والرسائل، ولا يحذف بياناتك، ويمكن تكراره.
4. إذا تبدأ بقاعدة جديدة، اختر ملفاً واحداً: `database/shineroster_with_demo.sql` للتجربة ببيانات مترابطة، أو `database/shineroster.sql` لتركيب نظيف دون حسابات تجريبية. لا تستورد ملف التركيب الكامل فوق جداول موجودة.
5. افتح `http://localhost/ShineRoster/`، وابدأ من صفحة تسجيل الدخول.

إعدادات الاتصال الافتراضية المحلية في `classes/Database.php`: قاعدة `shineroster`، المضيف `localhost`، المستخدم `root` وكلمة مرور فارغة. يمكن ضبط متغيرات البيئة `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` بدلاً من تعديل الكلاس. ملفات SQL تستخدم اسم القاعدة `shineroster`؛ إذا غيرته، عدّله أيضاً في ملف SQL الذي تستورده.

حافظ على ملفات `.htaccess` المرفقة، وتأكد أن Apache يسمح بها (`AllowOverride All`). تمنع تنزيل SQL وقراءة المجلدات الداخلية. أبقِ نسخة SQL القديمة خارج المجلد العام إذا كانت موجودة في نسختك السابقة. إذا كان الخادم لا يدعم `.htaccess` فلا تعتبر ملفات قاعدة البيانات محمية تلقائياً.

للتجربة باستخدام خادم PHP المدمج، من داخل مجلد `ShineRoster` شغّل:

```bash
php -S 127.0.0.1:8000 router.php
```

استخدام `router.php` ضروري لهذا الخادم لحماية الملفات الداخلية؛ خادم PHP المدمج للتطوير المحلي فقط. XAMPP لا يحتاج هذا الأمر.

## حساب تجربة مقدّم خدمة

- البريد: `provider1@shineroster.test`
- كلمة المرور: `ShineDemo!2026`

جميع حسابات البيانات التجريبية تستخدم كلمة المرور هذه. ملف التركيب النظيف لا ينشئها. عند النشر استخدم HTTPS ومستخدم قاعدة بيانات مخصصاً، ولا تنشر الحسابات التجريبية. أرقام الهواتف والبريد في البيانات أمثلة مصطنعة.

## التغييرات

- إصلاح مسار `init.php` وتنفيذ معالجة الدخول والتسجيل قبل إخراج HTML، مع عرض الأخطاء والاحتفاظ بالحقول غير السرية.
- منع التسجيل كأدمن، وفحص الاسم والبريد والهاتف وكلمة المرور والدور في الخادم.
- إنشاء حساب مقدّم الخدمة وملفه بعملية Transaction واحدة، مع مدينة فارغة مؤقتاً حتى يكمل ملفه. يتراجع إدخال المستخدم إذا فشل إدخال الملف.
- فحص دور الحساب وتفعيله من قاعدة البيانات قبل طلبات مقدّم الخدمة، وعدم الاعتماد على دور الجلسة وحده.
- جلسة مستقلة باسم `ShineRosterSession`، وتجديد معرفها عند الدخول، وCookies من نوع HttpOnly وSameSite=Lax وSecure عند HTTPS. تنتهي جلسة مقدّم الخدمة بعد 30 دقيقة خمول.
- إضافة CSRF للدخول والتسجيل والخدمات والتواصل، مع الإبقاء على حماية المواعيد والحجوزات والملف الشخصي والخروج.
- تقييد فشل الدخول لكل بريد إلى 10 محاولات خلال 15 دقيقة. توجد أيضاً حدود لكل عنوان IP: 30 طلب دخول و10 تسجيلات و5 رسائل تواصل خلال 15 دقيقة. التخزين في `auth_limits` يستمر عند تغيير الكوكيز. لا يتم الوثوق بترويسات البروكسي الواردة من المستخدم.
- التحقق من أطوال الخدمات والأسعار والمدد، ومعالجة المصفوفات والمدخلات غير الصالحة دون كشف أخطاء PHP/SQL.
- رفض نجاح تعديل خدمة غير موجودة أو تابعة لمقدّم آخر، والسماح بحفظ نفس البيانات دون تغيير. عمليات الخدمات تستخدم قفل مقدّم الخدمة نفسه المستخدم في المواعيد والحجوزات.
- إصلاح عنوان صفحة الخدمات وحالة عدم وجود نتائج، وربط الهيدر بنتيجة فحص الصلاحية المبكر.
- حسابات مقدّمي الخدمة التي فقدت ملفها بسبب خطأ التسجيل القديم تنتقل لاستكمال الملف بدلاً من تعطل صفحة الخدمات.
- تفعيل نموذج التواصل الموجود: تُحفظ الرسائل في `contact_messages` مع إشعار نجاح. لا تُرسل رسائل بريد إلكتروني، وعرض الرسائل في لوحة الأدمن مؤجل.
- نقل SQL إلى `database/` ومنع تنزيله، وإضافة ترويسات حماية ومنع تضمين الموقع في إطار وتشغيل السكربتات. صور صفحة الهبوط محفوظة محلياً داخل images/، وسياسة الصور تسمح بمصادر الموقع نفسه.
- وجهات الزبون والأدمن المؤجلة تعرض رسالة مؤقتة وحالة HTTP 503 بدلاً من صفحة فارغة/404؛ منطقة الأدمن وحجوزات الزبون المؤجلة تتحققان من الدور. هذه ليست واجهات مكتملة.
- نقل صور صفحة الهبوط الخارجية نفسها إلى `images/living-room.jpg` و`images/clean-home.jpg` حتى لا يعتمد ظهورها على طلبات خارجية.
- الحفاظ على الستايل والهيدر والفوتر والسايدبار المشترك. لم تتم إضافة أي JavaScript.

## قاعدة البيانات

أصبحت 10 جداول وواجهتي View: الجداول الثمانية الأصلية، إضافة إلى `auth_limits` و`contact_messages`.
ملف الترقية لا يغيّر أسماء الجداول والأعمدة الأصلية ولا يحذف بياناتها.

## نتائج الفحص وحدوده

نجح 173 اختباراً وظيفياً وأمنياً، وفحص صياغة 27 ملف PHP. التفاصيل والنتائج المفردة في مجلد `verification/`.
تم التنفيذ على PHP 8.3 وMariaDB 10.11 مع الوضع الصارم، وخادم PHP المدمج مع الراوتر، على قاعدة اختبار منفصلة. لم يجرِ التنفيذ على جهازك أو قاعدة بياناتك المحلية.

أُضيف فحص بصري بالصور وفحص للتخطيط عبر Chromium 151 وFirefox 153 وWebKit 26.5 في وضع headless. شمل 8 صفحات عند عروض 320 و390 و768 و800 و801 و1024 و1440 بكسل، مع فتح وإغلاق القائمة الجانبية وثبات الهيدر وعدم التمدد الأفقي وتحميل الصور. نجح 459 تحققاً إضافياً (153 لكل محرّك). WebKit هو محرّك Safari؛ لم نختبر تطبيق Safari على جهاز Apple أو أجهزة هواتف فعلية. لم يُشغّل Apache أو MySQL الأصلي في بيئة الاختبار؛ تمت مراجعة إعداد Apache وتوفير الراوتر الذي اختُبر فعلياً. هذه إصلاحات للعيوب والثغرات المكتشفة وليست ضماناً بخلو التطبيق من كل ثغرة ممكنة. وظائف الزبون والأدمن والبريد الإلكتروني والنشر خارج نطاق هذه النسخة.
